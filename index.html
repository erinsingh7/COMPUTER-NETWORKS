🎓 College Practical Lab Manual & Viva Documentation

📌 1. Aim of the Project

To design, develop, and test an interactive, responsive daily task manager web application titled “TaskFlow – Smart To-Do List” using standard HTML5, CSS3, and JavaScript, demonstrating rigorous client-side form validation, LocalStorage state persistence, HTML5 Drag-and-Drop item reordering, and deadline alert notifications.

🎯 2. Project Objectives

  • Input Validation & Error Handling: Prevent empty or whitespace-only submissions and deliver immediate visual feedback.
  • Browser Data Persistence: Implement the Web Storage API (localStorage) to maintain state across browser reloads without server-side database dependencies.
  • Interactive User Experience: Implement real-time task filtering (All, Pending, Completed), live keyword search, and dynamic task counters.
  • HTML5 Drag-and-Drop API: Enable intuitive manual task reordering via browser-native drag events.
  • Web Notification API: Check scheduled deadlines and trigger push alerts and synthesized Web Audio notifications.
  • Modern Aesthetic Standards: Develop a clean, mobile-responsive layout utilizing modern CSS variables, flexbox, and CSS grid.

💻 3. Software & Hardware Requirements

  • Operating System: Any OS (Windows 10/11, macOS, Ubuntu/Linux).
  • Web Browser: Google Chrome, Mozilla Firefox, Microsoft Edge, or Apple Safari (supporting ES6, LocalStorage, and HTML5 Drag & Drop).
  • Editor / IDE: Visual Studio Code, Sublime Text, or Notepad++.
  • Hardware: Minimum 2 GB RAM, Dual-core CPU, 100 MB free disk space.

📚 4. Brief Technical Theory

A. Document Object Model (DOM) Manipulation: The browser parses HTML into an object tree. JavaScript interacts with this tree using methods such as document.getElementById(), createElement(), and appendChild() to dynamically add, edit, and delete task cards without reloading the page.

B. Web Storage API (LocalStorage): Unlike transient session memory, localStorage provides persistent key-value client storage with ~5MB capacity. Data is serialized with JSON.stringify() before storage and parsed with JSON.parse() upon retrieval.

C. HTML5 Drag and Drop API: Elements marked with draggable="true" fire lifecycle events including dragstart, dragover, dragleave, and drop. The dataTransfer object passes identifier tokens to recalculate array positions.

D. Browser Notification API: Facilitates desktop notifications outside the active tab via Notification.requestPermission() and new Notification(title, options).

⚙️ 5. Algorithms

Algorithm 1: Adding a Task with Input Validation

  1. Start when user clicks "Add Task" or presses the Enter key.
  2. Read taskInput.value and apply .trim() to strip leading and trailing whitespace.
  3. Condition Check: If trimmedText === "":
    • Display validation warning: "Task description cannot be empty or contain only spaces."
    • Add CSS class input-error to trigger visual shake animation.
    • Set focus back to taskInput and Exit without modifying state.
  4. If valid, generate unique identifier id = 'task_' + timestamp + randomKey.
  5. Construct task object: { id, text, completed: false, priority, category, deadline, createdAt }.
  6. Prepend object to tasks array via tasks.unshift(newTask).
  7. Serialize and persist: localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks)).
  8. Reset form input values, display success toast notification, and call renderTasks().
  9. End.

Algorithm 2: Reordering via HTML5 Drag and Drop

  1. On dragstart, record source task ID into draggedTaskId.
  2. On dragover, invoke e.preventDefault() to permit dropping and add hover highlight class.
  3. On drop, identify target task ID from card.dataset.id.
  4. Find array indexes: fromIndex and toIndex.
  5. Splice task from fromIndex and re-insert at toIndex.
  6. Invoke saveTasksToStorage() and renderTasks().

💬 10. Top 5 Viva Questions & Model Answers

Q1: What is the difference between LocalStorage and SessionStorage?
Answer: Both are part of the Web Storage API and store data as key-value pairs (~5MB per origin). However, localStorage persists indefinitely until explicitly cleared by the user or script, whereas sessionStorage is purged as soon as the browser tab or session is closed.
Q2: How do you prevent empty tasks or space-only input in JavaScript?
Answer: By reading the input string and calling the built-in trim() method (e.g., const cleanText = taskInput.value.trim()). If cleanText === "", the submission is rejected, preventing users from creating blank or accidental whitespace entries.
Q3: What is Event Delegation and why is it useful in a dynamic to-do list?
Answer: Event Delegation is a technique where a single event listener is attached to a parent element rather than attaching individual listeners to every dynamically created child. Through event bubbling (capturing/target phase), the parent inspects event.target to handle actions efficiently with lower memory overhead.
Q4: How does the HTML5 Drag and Drop API function in TaskFlow?
Answer: Task cards are given the attribute draggable="true". On dragstart, the dragged task's ID is stored. When hovered over another task (dragover, with e.preventDefault()), a visual drop marker is shown. On drop, the array items are spliced and repositioned, followed by saving to LocalStorage.
Q5: How does the Web Notification API work and why is explicit permission mandatory?
Answer: The Web Notification API allows web pages to display system-level alerts outside the viewport. For security and user privacy, browsers enforce an explicit opt-in flow via Notification.requestPermission(). Notifications are only dispatched if the user explicitly grants approval.

🚀 Step-by-Step GitHub Pages Free Deployment Guide

Deploying TaskFlow on GitHub Pages is 100% free and takes less than 2 minutes. Follow these exact steps:

📁 1. Project Directory Structure

Ensure your folder on your computer contains the three files in the root folder without subfolders:

my-taskflow-app/ ├── index.html (Main HTML file) ├── style.css (CSS stylesheet) └── script.js (JavaScript logic)

📦 2. Create a Free GitHub Repository

  1. Open github.com and sign in (or create a free student account).
  2. Click the "+" icon at the top-right and select New repository.
  3. Set the Repository name to taskflow (or any name you prefer).
  4. Select Public (GitHub Pages is free for all public repositories).
  5. Leave "Initialize with a README" unchecked, then click Create repository.

📤 3. Upload the 3 Files

  1. On the newly created repository page, click the link: "uploading an existing file".
  2. Drag and drop the three files: index.html, style.css, and script.js into the box.
  3. Under Commit changes, enter Initial release of TaskFlow and click Commit changes.

⚙️ 4. Enable GitHub Pages Hosting

  1. In your repository, click the Settings tab at the top.
  2. In the left sidebar menu, click on Pages (under "Code and automation").
  3. Under Build and deployment > Source, ensure Deploy from a branch is selected.
  4. Under Branch, choose main (or master) from the dropdown, leave the folder as / (root), and click Save.

🌐 5. Obtain Your Live Website URL

GitHub will automatically build your site. Wait approximately 30 to 60 seconds and refresh the Pages settings screen. You will see a banner:

✓ Your site is live at: https://<your-github-username>.github.io/taskflow/

You can copy this link and paste it directly into your college practical report or send it to your professor during viva evaluation!
